# Writing

## Use the required language

Apply the available `output` skill to responses and project text.
Use strict ASD-STE100 Simplified Technical English as the writing quality standard.
Reply to the user in Chinese unless they request another language.
For requested rewrites, use the requested language and style.
Write other project documents and comments in strict Simplified Technical English.

## Write current contracts

Get an explicit request before you create or modify explanatory documents or manifests.
Normal Trellis task, research, context, spec, and journal artifacts are exceptions to this requirement.
Keep only current rules in specs.
Do not put adoption records, source-project stories, or decision identifiers in spec bodies.

Describe the current API contract and actual behavior.
Do not promise behavior that the implementation does not provide.
Use comments to explain the current purpose or constraint.
Retain valid regression context when it explains a current requirement.

## Preserve attribution

Use the actual copyright owner.
Retain required upstream and dependency attribution.
Do not copy unrelated copyright notices into the project.
